# 自定义回复插件（astrbot_plugin_reply）

`astrbot_plugin_reply` 是 AstrBot 的关键词回复插件，提供规则创建、编辑、删除、导入导出和统计管理，并通过 AstrBot 官方插件可视化视图运行。

## 功能特点

- 精确、包含、前缀和正则四种匹配方式，支持大小写敏感设置、消息 Unicode 规范化和稳定的优先级排序。
- 一个规则可以绑定多个关键词，一个关键词也可以被多条规则使用；默认只执行最高优先级的有效规则。
- 固定文本、随机文本、多段文本和原生 AstrBot 多媒体消息链回复，支持图片、视频、语音、文件和 At。
- 回复文本统一支持 `{sender}`、`{nickname}`、`{group_id}`、`{group_name}`、`{time}`、`{date}`、`{random}`。
- 每条规则可独立设置黑名单/白名单作用域、规则/用户/群聊冷却、每日次数和允许时间段。
- 规则触发次数与最近触发时间写入插件数据目录，重载或重启后仍然保留。
- 使用 AstrBot 官方 `views/` 插件视图和 `window.AstrBotPluginView` bridge，不启动额外 HTTP 服务，不引入大模型 API。

## 安装

在 AstrBot WebUI 的插件市场中安装 `https://github.com/yiyinfaith/astrbot_plugin_reply`，或将本目录放入 AstrBot 的 `data/plugins/astrbot_plugin_reply` 后重载插件。当前支持 AstrBot `>=4.18,<5`。

数据会写入 `StarTools.get_data_dir("astrbot_plugin_reply")` 返回的插件数据目录，代码仓库不会保存用户规则、统计、运行日志或缓存。

## 打开 WebUI

1. 登录 AstrBot 管理面板。
2. 打开「插件」并进入「回复管理」详情页。
3. 在插件可视化视图中打开「回复管理」。
4. 左侧导航包含总览、规则列表、创建规则、导入/导出、触发统计和全局设置。

所有管理 API 都通过 AstrBot 管理端认证。后端还会检查可选的 WebUI 管理员账号列表；删除规则必须在浏览器中二次确认并在 API 中提交 `confirm=true`。

## 创建规则

在「创建规则」中填写：

- 规则名称和关键词：每行一个关键词。
- 匹配方式：精确、包含、前缀或正则；正则会在保存时校验。
- 大小写：关闭时使用 Unicode `casefold()`，并统一折叠连续空白。
- 回复类型：固定文本、随机文本、多段文本或多媒体消息链。
- 作用域：默认黑名单，填写群号或用户 ID 后排除这些对象；切换为白名单后仅允许列表中的对象。
- 优先级：数值越大越优先；同优先级会按匹配方式、关键词长度、规则 ID 稳定排序。
- 冷却与限制：规则冷却、同一用户冷却、同一群聊冷却、每日触发上限和允许时间段均可独立设置。留空或填 `0` 表示不限制。

表单底部的「规则测试」只做本地匹配和变量预览，不写入统计，也不会向聊天平台发送消息。

## 匹配顺序

插件先检查全局和规则作用域，再检查启用状态、时间段、冷却和每日次数。通过限制后，按规则优先级降序选择；同优先级依次按精确、前缀、包含、正则，再按匹配关键词长度和规则 ID 排序。这样可以在多规则冲突时得到稳定结果。

默认设置要求消息是 @机器人或 AstrBot 唤醒命令，和旧版行为一致。需要让普通消息参与匹配时，在「全局设置」关闭「仅响应 @机器人或唤醒命令」。

## 动态变量

| 变量 | 含义 |
| --- | --- |
| `{sender}` | 发送者 ID |
| `{nickname}` | 发送者昵称 |
| `{group_id}` | 群号，私聊为空 |
| `{group_name}` | 群名称（平台提供时） |
| `{time}` | 当前时间，`HH:MM:SS` |
| `{date}` | 当前日期，`YYYY-MM-DD` |
| `{random}` | 当前回复生成的随机数 |

变量替换使用统一的安全替换器，不调用用户可控的 `str.format()`，未知占位符会原样保留。

## 多媒体消息链

在回复类型选择「多媒体消息链」后，可按发送顺序添加图片、视频、语音、文件和 At。图片、视频、语音可填写平台可访问的 URL 或 AstrBot 进程可访问的本地路径；文件可同时填写显示名；At 组件填写目标用户 ID。发送时使用 AstrBot 原生 `Image`、`Video`、`Record`、`File` 和 `At` 组件，由平台适配器负责兼容处理。

规则和设置使用 `reply_rules.json` 保存，并通过同目录临时文件加 `os.replace()` 原子替换写入。统计和冷却数据与规则一起持久化；插件不会访问或覆盖其他插件的数据目录。

## 导入与导出

「导出」会下载包含 `schema_version`、规则和全局设置的 JSON 文件。「导入」会先在浏览器中确认，再由后端逐条校验正则、回复类型、时间段和消息组件；校验通过后原子替换当前规则。建议在批量修改前先导出备份。
